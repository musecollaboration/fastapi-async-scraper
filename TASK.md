# Техническое задание: Асинхронный парсер каталога с REST API и веб-интерфейсом

## Цель проекта
Разработать Proof of Concept (PoC) сервиса для сбора данных с сайта-каталога. Проект должен демонстрировать навыки работы с асинхронным Python, парсингом HTML, экспортом данных и созданием API на FastAPI.

**Целевой сайт:** `https://books.toscrape.com/` (песочница для парсинга).

## Технологический стек
*   **Язык:** Python 3.10+
*   **Бэкенд:** FastAPI, Uvicorn
*   **Парсинг:** httpx (асинхронные запросы), BeautifulSoup4 (разбор HTML)
*   **Работа с данными:** pandas (экспорт)
*   **Валидация:** Pydantic v2
*   **Фронтенд:** HTML5, Tailwind CSS (CDN), Vanilla JS

## Функциональные требования

### 1. Модуль сбора данных (`scraper.py`)
*   Написать асинхронную функцию `fetch_category(category_url: str, max_pages: int)`.
*   **Эмуляция защиты:** Реализовать задержку `asyncio.sleep(1)` перед каждым запросом (имитация обхода антибота) и отправку браузерных заголовков (User-Agent).
*   **Ретраи:** При ошибках `429` или `5xx` делать до 3 повторных попыток с экспоненциальной задержкой (backoff).
*   **Парсинг:** Извлекать данные из тегов `<article class="product_pod">`.
*   **Пагинация:** Обходить страницы согласно параметру `max_pages` с дедупликацией товаров по URL.
*   **SKU:** Генерировать детерминированный артикул (например, через `uuid5`), чтобы не делать лишние запросы на страницу каждого товара.

### 2. Схемы данных (`schemas.py`)
Создать Pydantic-модели с валидацией:
*   `Product`: `category_lvl1`, `subcategory_path`, `name`, `image_urls`, `product_url`, `sku`.
*   `ParseRequest`: `category_url` (с валидацией на разрешенный хост для защиты от SSRF), `max_pages` (от 1 до 50).
*   `ParseResponse`: `status`, `items_count`, `csv_file`.

### 3. Экспорт данных (`exporter.py`)
*   Написать функцию сохранения в CSV через `pandas`.
*   **Требования к файлу:** Кодировка `utf-8-sig` (для корректного отображения кириллицы в Excel), разделитель `;`.
*   **Заголовки:** На русском языке (Категория, Подкатегория, Наименование, Ссылка на фото, Ссылка на товар, Артикул).

### 4. REST API (`main.py`)
*   `POST /parse`: Принимает URL и количество страниц, запускает парсинг, сохраняет CSV и возвращает JSON с результатом (количество собранных товаров и имя файла).
*   `GET /download/{filename}`: Эндпоинт для скачивания готового CSV-файла (с защитой от Path Traversal).
*   `GET /health`: Проверка статуса сервера.

### 5. Веб-интерфейс (`index.html`)
*   Минималистичный дизайн (темная тема, Tailwind CSS).
*   Форма с полями для URL и количества страниц.
*   Кнопка «Запустить парсинг» с индикатором загрузки (спиннер).
*   Блок для вывода результата («Успешно собрано: X товаров») и кнопки скачивания CSV.
*   Обработка и вывод ошибок (например, неверный URL).
*   Сервер FastAPI должен отдавать этот интерфейс по корневому маршруту `GET /`.

## ✅ Критерии приемки (Definition of Done)
1.  Скрипт успешно парсит данные с целевого сайта (проверено на 1 и 2 страницах).
2.  CSV-файл корректно открывается в Excel (разделитель `;`, кириллица не искажена).
3.  Swagger UI (`/docs`) доступен и позволяет тестировать API.
4.  Веб-интерфейс работает: кнопка запускает парсинг, и файл успешно скачивается.
5.  Код структурирован по модулям, присутствует файл `requirements.txt` и `README.md` с инструкцией по запуску.
